# External 2026 benchmark query archive integrity audit: declared 40, actual 32

**Source**: LargeRDFBench Interoperable Edition, Zenodo 22140177, published August 28, 2026, DOI https://doi.org/10.5281/zenodo.22140177. The source record says a total **40** queries, S1-S14 (14), C1-C10 (10), L1-L8 (8), CH1-CH8 (8). URL https://zenodo.org/records/22140177

**Direct-source evidence**: workflow https://github.com/AiDevnew168/scale_rag/actions/runs/44919826851, artifact https://github.com/AiDevnew168/scale_rag/actions/runs/44919826851/artifacts/14713256821. Real `queries.zip` downloaded from Zenodo, checksum **MD5 `10a2e5fb7a69ff9da66d9d5bf977a77e`** verified against the published digest. File decoded with zip-bomb, original UTF8 and traversal safety guards; no original queries edited.

**Observed source discrepancy**: only **32** SPARQL query files present, named `S1..S14`, `C1..C10`, and `B1..B8`; the claimed `L1..L8` and `CH1..CH8` are not present under those names. All 32 of the **actually supplied** public source queries parsed under both RDFLib 7.5.0 and pyoxigraph 0.5.13 syntax on an empty store. The deliberately narrow original constant-BGP compiler supports **9/32**, all with at least one constant predicate-triple anchor, while **23/32** require other SPARQL operators. These are SOURCE syntax/structure observations, not RDF expected-result compatibility or full federation execution.

The unmodified [original LargeRDFBench GitHub repository](https://github.com/dice-group/LargeRDFBench/tree/master/BigRDFBench-Utilities/queries) also contains 32 files of the same `B`, `C`, `S` families. That explains the legacy naming but does **not** resolve the inconsistency with the later published Zenodo 40-query inventory. We do not invent, silently generate or select the claimed missing queries; the strict external workflow correctly ended **failure** on this metadata mismatch. The 32 source-file subset can be used in an explicitly renamed *partial* source-only diagnostic, but not called the full published 40-query test suite.

Paper related to benchmark integrity: [Tam, Saleem and Taelman, 2026](https://arxiv.org/abs/2608.30465) demonstrates data/RDF and result-answer interoperability problems. Our independently observed 40-vs-32 archive inventory discrepancy is an additional practical caution to resolve with maintainers before full-scale use; it is not an original query algorithm or proof of a new 2026 paper error beyond what the available record says.

**Future role**: this suite lacks natural original per-query calendar timestamps, so even a successful multi-host original-result comparison could test SPARQL interoperability/semantic correctness and performance on published queries, but not prospective 2014 SWDF temporal migration economics. The 13 datasets total >1 billion triples with a 5.1GB zipped RDF artifact; do not load all of them on a resource-limited runner just to get a green workflow. Require an externally version-aligned dataset, fully published query/result inventory, strong federated engine baseline and real network before journal SOTA claims.
